# Редизайн клиентского потока на @telegram-apps/telegram-ui — дизайн

Дата: 2026-07-30
Статус: черновик, ожидает ревью пользователя

## 1. Контекст и рамки

Текущий клиентский UI (Tasks 14-16 предыдущего плана) — голая семантическая HTML-разметка без визуального дизайна: `<h1>`, `<p>`, `<ul>`/`<li>`, инлайновые стили только для цвета (через `--tg-theme-*` CSS-переменные). Задача — заменить разметку на компоненты `@telegram-apps/telegram-ui` (официальный UI-кит от разработчиков `@telegram-apps/sdk-react`, уже используемого в проекте), сохранив всю существующую бизнес-логику, хуки (`useMainButton`, `useBackButton`, `useTelegramTheme`, `useBusinessSettings`) и API-слой без изменений.

**В рамках этого захода:** 4 клиентских экрана — список услуг (`ServicesList`), выбор даты/времени (`SelectSlot`), подтверждение (`Confirm`), мои записи (`MyBookings`).

**Вне рамок:** админ-панель (`AdminLayout`, `AdminBookings`, `AdminServices`) остаётся в текущем виде — редизайн будет отдельным заходом позже. `MainButton`/`BackButton` остаются нативными Telegram-компонентами (уже корректно работают, `telegram-ui` их не заменяет — это компоненты для контента внутри экрана, не для системной навигационной хромы).

`@telegram-apps/telegram-ui` не содержит компонента календаря/date-picker (проверено по составу пакета: `Cell`, `List`, `Section`, `Chip`, `Button`, `Banner`, `Spinner`, `Select`, `SegmentedControl` и т.д. — календаря нет), поэтому календарная сетка строится вручную на примитивах библиотеки.

## 2. Архитектура интеграции

`frontend/src/App.tsx` оборачивает дерево в `<AppRoot>` из `@telegram-apps/telegram-ui`. `AppRoot` принимает `platform` (`'ios' | 'base'`) и `appearance`/`class` для цветовой схемы:
- `platform` — определяется через launch params (`tgWebAppPlatform`, доступно через `@telegram-apps/sdk-react`'s `useLaunchParams`/`useRawLaunchParams`, уже подтверждённые рабочие экспорты пакета — см. Task 13), значение `'ios'`/`'macos'` маппится в `'ios'`, всё остальное — в `'base'`, с фолбэком `'base'` вне Telegram. Точное имя сигнала/экспорта для платформы проверяется по установленной версии пакета в момент реализации (по аналогии с тем, как уточнялись `mount`/`isAvailable` для `mainButton`/`backButton` в предыдущем плане) — не подтверждено заранее, чтобы не повторить ошибку с предположениями об API SDK.
- Цветовая схема — `@telegram-apps/sdk-react` экспортирует сигнал `isDark` в области `themeParams` (подтверждено по составу пакета при работе над Task 12, но в `useTelegramTheme.ts` сейчас не используется — там используется только `mountThemeParamsSync`/`isThemeParamsMounted`/`bindThemeParamsCssVars`). Для `AppRoot` добавляется новое использование этого сигнала — не переиспользование существующего кода, а новая, но подтверждённо существующая точка интеграции.

`useTelegramTheme()` (Task 12) не меняется — `telegram-ui` компоненты сами используют `--tgui--*` CSS-переменные, которые `AppRoot` синхронизирует с `--tg-theme-*` при монтировании. Оба набора переменных сосуществуют без конфликта.

`main.tsx`'s `import 'telegram-web-app.js'`/`init()` try/catch (Task 18 фикс) не меняется — `AppRoot` не требует отдельной инициализации SDK, только читает уже доступные сигналы.

## 3. Экраны

### 3.1 Список услуг (`ServicesList.tsx`)

- `Placeholder` (иконка + текст) вместо `<p>Загрузка...</p>` / `<p>Не удалось загрузить услуги</p>`.
- `List` → `Section` → `Cell` на каждую услугу: `Cell.title` = название, `Cell.subtitle` = `{price} ₽ · {durationMinutes} мин`, `Cell.after` = шеврон (навигация на `/booking/:id`), весь `Cell` — `Link`-обёртка (как сейчас).
- Ссылка "Мои записи" — `Cell` с иконкой в отдельной `Section` внизу списка, либо `Link` компонент telegram-ui.

### 3.2 Выбор даты и времени (`SelectSlot.tsx`)

- **Календарная сетка** (новый компонент `frontend/src/components/DateGrid.tsx` или инлайн в `SelectSlot`): CSS grid 7 колонок (дни недели, локализация RU: Пн-Вс), ячейки — `Chip` (компактный) или `Cell` (крупнее, зависит от того, как будет выглядеть на практике — решается в момент вёрстки). Диапазон: от сегодня (в таймзоне бизнеса, уже верно вычисляется через `useBusinessSettings`) до `today + bookingHorizonDays`. Ячейки вне диапазона — `disabled`, визуально приглушены (`Chip`/`Cell`'s `disabled`/`mode="disabled"` проп, если есть, иначе — сниженная opacity через `--tgui--*` переменную). Показывается только текущий месяц и, если горизонт заходит в следующий, — следующий месяц (навигация вперёд/назад ограничена этим диапазоном, не произвольная).
- Сетка времени под календарём — `Section` с `Chip`-рядом (текущая логика выбора остаётся, просто визуальные обёртки меняются с `<button>` на `Chip`).
- `Spinner` вместо "Загрузка...".

### 3.3 Подтверждение (`Confirm.tsx`)

- `List`/`Section` с `Cell`-строками: имя клиента, услуга, дата/время, цена.
- Ошибка 409 — `Banner` (mode="destructive" или аналог) вместо `<p role="alert">`, сохраняя `role="alert"` для доступности (добавляется как проп/обёртка, если `Banner` сам не выставляет).

### 3.4 Мои записи (`MyBookings.tsx`)

- `List` → `Section` → `Cell` на бронь: `Cell.title` = услуга, `Cell.subtitle` = дата/время, `Cell.after` = `Badge` со статусом ("Подтверждена"/"Отменена", разными цветами через `Badge`'s `type`/`mode`).
- Кнопка "Отменить" — `Button` (`mode="destructive"` или `size="s"`), показывается только для `status === 'confirmed'` (логика не меняется).

## 4. Тестирование

Существующие тесты (`ServicesList.test.tsx`, `SelectSlot.test.tsx`, `Confirm.test.tsx`, `MyBookings.test.tsx`) мокают API-модули (`getServices`, `getSlots`, `createBooking`, `getWhoAmI`, `getMyBookings`, `cancelBooking`) и SDK-хуки (`useMainButton`/`useBackButton`/`useBusinessSettings`) — эта часть моков не меняется. Меняются только селекторы внутри тестов (`getByText`/`getByRole`), так как разметка меняется с `<p>`/`<button>`/`<div>` на компоненты `telegram-ui` (которые рендерят semantic HTML под капотом, но с другой структурой/классами). Регресс-тесты на `isPending`-паттерн (найденные в Task 18 финального ревью) — логика хуков не трогается, тесты должны остаться рабочими без изменений содержания, только возможно потребуют поправки в selector для проверки состояния loading (если Placeholder/Spinner меняют доступный текст).

Новый тест: `DateGrid`-компонент (или встроенная в `SelectSlot` логика генерации сетки) — юнит-тест на генерацию календаря для заданного `bookingHorizonDays` и текущей даты, проверяющий: правильное количество активных/disabled ячеек, корректную границу горизонта, отсутствие ячеек за пределами текущего+следующего месяца свыше необходимого.

## 5. Зависимости

Добавляется `@telegram-apps/telegram-ui` (последняя стабильная версия на момент установки — `^2.1.13` на момент написания спеки, точная версия фиксируется в `package.json` при реализации) в `frontend/package.json`. Никаких новых зависимостей для календаря не требуется (пишется на примитивах `telegram-ui`).
